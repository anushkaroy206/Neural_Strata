1. The Whole System — one picture

Four surface sensor nodes talk wirelessly (ESP-NOW) to the Main Hub. The Main Hub is the single bridge: USB serial up to the laptop, and a wired ring backbone down into the mine to the two Level Hubs (your “servant hubs”), each driving 2 junction LED strips, 1 RFID gate and 1 siren.

Everything wireless is dashed blue (no wires). The only wires are: USB (hub→laptop), the 3 ring hops, and each board’s own power. All logic levels are 3.3 V — no converters anywhere.

Rules: ① always cross TX↔RX (never TX→TX) ② one shared GND bus — non-negotiable ③ 115200 baud, 8N1 ④ put a toggle switch in series with W4 (or hop-2 GND) for the clean “wire cut” demo. No level shifters needed — everything is 3.3 V ESP32.

Topology note — bidirectional (full-duplex) triangle, not a one-way ring.
Each hop has two separate wires (one TX per direction) → true full-duplex, simultaneous both ways — no time-slots, no half-duplex switching, no MAX485. With 3 hubs this forms a triangle: every hub is directly linked to both neighbours, so there are always two paths between any pair. Failure math: 0 cuts → all direct · 1 cut → all 3 hubs still directly connected (Case C demo, zero relaying) · 2 cuts → one hub isolates (documented limit). A unidirectional circulating ring would die on a single cut (which is why FDDI needed dual counter-rotating rings) — full-duplex per hop is what makes one-cut survivability free. RS-485 half-duplex would use the same 7 wires (each hop still needs 2 conductors) plus transceivers and arbitration — no benefit at 3 nodes; kept as the production backbone per SRS.

3. Normal Operation — the two flows

Flow 1 · UPLINK (sensors → screen) — continuous, 2 Hz

1Node firmware samples MPU-6050 (I2C) + pot (ADC) every 500 ms.

2Sends {"node":2,"seq":481,"disp":12.3,"tilt":0.4,"acc":0.02} by ESP-NOW to the hub and its two ring neighbours (they store it — this is what makes relay possible).

3Main hub forwards every packet as a JSON line over USB serial to Flask.

4Flask ticker (500 ms): updates state, computes v/a, writes PostgreSQL (2 Hz), pushes to 60 s model buffers.

5Every 1 s the XGBoost model predicts TTF per node (or kinematic fallback).

6Dashboard polls /api/telemetry + /api/ai every 500 ms → gauges, TTF pill, GIS map update.

Flow 2 · DOWNLINK (decision → mine) — on alert

1Status logic flips a node to WARNING/CRITICAL (a > 0.25 / a ≥ 3.0 mm/s²) → route state BLOCKED.

2Server writes alert commands over serial: {"cmd":"route","level":1,"route":"A","state":"BLOCKED"}, {"cmd":"siren","level":2,"on":true}, {"cmd":"rfid_zone","level":1,"zone":"Safe Exit"}.

3Main hub relays down the ring (hop 1 → L1; hop 3 → L2; heartbeats every 2 s keep the ring alive).

4Level Hub lights its 2 junction strips green→red on blocked routes, fires the siren, and re-maps the RFID gate zone.

5Simultaneously the alert engine fires email + SMS to the Safety Officer’s phone.

6RFID swipes flow back UP the ring → live mustering headcount on the dashboard.

4. Every Failure Case — what breaks, what happens, what the judges see

CASE A Surface node’s direct link degrades (N2) → mesh relays the data

What happens: hub detects missing seq numbers from N2 → requests them → N1 retransmits (N3 is the backup). No data lost, no model impact — the TTF countdown keeps running on N2’s relayed values.

Dashboard: N2 card badge → N2 · via relay (N1) · event log: “Mesh reroute: N2 via N1 (seq 482–489)” · TTF pill: unaffected

Demo move: cover N2’s antenna (or flip its “relay-only” switch) for 10 s → badge appears → uncover → back to direct. “Kill a link, the mesh heals in <2 s.”

CASE B Node destroyed (N3 powered off) → Last-Gasp packet + sacrificial-hardware story

What happens: N3’s brownout interrupt fires one final Last-Gasp packet → hub marks N3 OFFLINE → mesh keeps running with 3 nodes → surviving N1/N2/N4 define the collapse boundary (“crater mapping” story).

Dashboard: N3 card → OFFLINE · last-gasp received 14:02:33 · GIS map: N3 red ×, zone polygon shaded · event: “N3 terminal anomaly — final values logged” · other nodes: normal

Demo move: flip N3’s power switch → burst of red → hold 10 s for the judges. “Even destroyed, the node reports.”

CASE C Ring backbone wire cut (L1 ↔ L2) → ring heals, both levels stay live

Dashboard: underground schematic → L1↔L2 segment: RED (broken) · reroute: direct via MAIN — all hubs live · L2 junctions + siren + RFID: still receiving alerts

Demo move: flip the hop-2 switch → red segment on screen → wave at L2’s LEDs: still flashing alerts. “Cut the mine’s spine — it walks on the other leg.”

CASE D AI model file removed → graceful degradation (FALLBACK)

What happens: server boots normally, /api/ai reports FALLBACK, TTF pill runs on Fukuzono kinematics. Restore models/ → restart → ACTIVE in ~60 s.

Demo move: mv models models_bak && restart in front of the judges. “Break the AI — the system degrades, it never dies.”

CASE E (optional) LoRa node at distance → range proof, same pipeline

Proof that the mesh is transport-agnostic: Wi-Fi P2P on the diorama, LoRa in the field — backend, model and dashboard untouched.
